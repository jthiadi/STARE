Pipeline: part + verb → action, where the part is, which SOP step is done

A1: part branch (ours). A2: verb branch (verb team); both meet at action = verb + part. B: where the part is, and which SOP step is done, including the planned car-state detector (ASD) and step recognition (PSR). Icons show how each block is trained.

  • Two training stages. Stage 1: the green DINOv2 is fine-tuned on hand-area crops with part and verb labels, in two halves so no training video is described by a model that saw it. Stage 2: both DINOv2 copies are kept fixed and only the TCN and its heads are trained.
  • Two parallel branches, same design. Both branches go frame features → MS-TCN → weighted result / ensemble → decoding / smoothing. The part branch (A1) uses DINOv2-S only; the verb branch (A2) uses several feature extractors. Whether the verb team's extractors are frozen or fine-tuned is not confirmed yet (❔).
  • Who decides what. DINOv2 only describes each frame; the TCN decides the part name and confidence; SAM only finds where that part is. SAM's own part name is not used for the label.
  • Viterbi smoothing has no gradient training: its part-to-part switching costs are counted from the training labels.
  • Offline parts (orange text): the TCN's look-ahead and Viterbi smoothing need the whole recording.
  • ASD and PSR (planned, bottom row of B). ASD looks at the car, not the hand: YOLOv8 (COCO-pretrained, fine-tuned on IndustReal's state labels) outputs the car's 11-digit state each frame. PSR is rules, not a model: a step counts as done when the state flips, confirmed by a matching action from A, and only if the SOP allows it. Baseline first: ASD + SOP only (the paper's B3, F1 0.883); then add the action evidence to shorten the delay. PSR's step state replaces today's SOP step rules and drives the wrong-part alarm.
  • Data: trained on 18 assembly videos (9 people); the test video 13_assy_0_1 and its labels are never used in training.

Our implementation: what we built

❄️ Used as is

  • SAM 3.1 (frozen), with our text prompts for the 15 kit parts + hand
  • DINOv2-S, frozen copy (Meta's pretrained weights)
  • MS-TCN architecture (Farha & Gall, CVPR 2019): stacked stages of dilated convolutions

🛠️ Adapted by us

  • DINOv2 fine-tuned on hand crops with part + verb labels; 2-half cross-fitting so no video is described by a model that trained on it
  • Multi-view input: 4 fixed crops per frame (full, centre, hands, high-res hands)
  • MS-TCN training recipe: verb helper task, rare-part weighting, time warp, ensemble of 36 TCNs
  • Decoding: Viterbi with a part-order prior learned from training labels + a "nothing" threshold

⭐ Built by us

  • Hand-contact picker + tracker: places the recognised part's box with no box labels and no training
  • Pipeline design: perception never reads the SOP; the SOP only judges what was seen
  • Evaluation: per-frame and per-segment scoring against the official labels; held-out-person test
  • SOP step rules (baseline, to be replaced by PSR)

How two key blocks work

Multi-stage TCN (temporal encoding) 🔥

Reads the DINOv2 features of every frame of the video and outputs, for every frame, scores for 15 part classes (13 kit parts + partial model + nothing) and 10 verbs.

How it works

  • Dilated convolutions: each layer mixes a frame with neighbours 1, 2, 4 … 512 frames away, so after 10 layers each frame's answer uses about ±100 s of video around it (context such as "a tooth washer was just fitted").
  • Stage 1 reads the DINOv2 features and makes a first guess. Stages 2–4 see only the previous stage's guesses and learn to clean up typical mistakes: flicker, one-frame blips, impossible part orders.
  • "Part head" and "verb head" are the two halves of each stage's output layer (first 15 outputs / last 10), not separate models.
  • Size: 192 internal numbers per frame in each layer.

How it is trained (one training run, everything at once)

  1. Input one whole training video's saved features at a time, randomly sped up or slowed down a little (time warp).
  2. All 4 stages predict part + verb for every frame.
  3. Loss, summed over all 4 stages: cross-entropy on the part (rare parts weighted up) + 0.5 × cross-entropy on the verb + a small smoothness penalty against jumpy answers.
  4. Update all weights of all stages together (AdamW, learning rate slowly decreasing). 80 passes over the training videos.

Ensemble

  • 18 training videos split into 6 groups; for each group, 3 TCNs (different random starts) are trained on the other 15 videos → 18 TCNs per variant, 2 variants (with / without verb head) → 36 TCNs.
  • At test time all of them predict; probabilities are averaged (variants weighted 0.6 / 0.4), then Viterbi smoothing picks one part per frame.
  • DINOv2 is not changed here: its features were computed beforehand.

Hand-contact picker + tracker ⚙️

SAM 3.1 outlines every part and both hands in the frame. The picker chooses the one outline that is the part in the hand, using the part name from the TCN. No learning; fixed rules (monitor/in_hand.py).

Every frame

  1. Hand zone: join all SAM hand outlines and widen them by 12 px.
  2. Look-alike filter: keep only SAM outlines whose SAM name is in the same look-alike group as the TCN's part (SAM often confuses these):
    GroupMembers
    small round partsnut, tooth washer, round washer, acorn nut
    pinspin short, pin middle, pin long, screw pin
    white frame partsshort brace, long brace, front bracket, wing, base
    kept separatepulley and wheel (pink spool vs black tyre)
  3. Must touch a hand: at least 25 pixels and at least 4% of the outline inside the hand zone. Outlines bigger than 8% of the frame are skipped (e.g. the whole chassis).
  4. Score each remaining outline:
    RuleEffect
    share of the outline touching the handbase score, 2 × share, max 1.0
    SAM's name exactly equals the TCN's part+0.25
    same object as last frame (tracking)+0.15
    has not moved: same place (box overlap ≥ 0.7) 1.5 s and 3 s ago−0.35 (already fitted on the car, not in hand)
  5. Pick the highest score. Nothing qualifies → no box this frame (the overlay says "not located in hand"), rather than a wrong box.
  6. Label: the box shows the TCN's part + confidence (e.g. "nut 0.93"), never SAM's own name.

Tracking

  • SAM keeps an ID for each object across frames. The chosen object's ID is remembered; next frame it gets the +0.15 bonus, so the box stays on the same physical part instead of jumping between two similar nuts.
  • The lock is dropped as soon as the TCN's part changes (e.g. nut → wheel), so the picker can move to the new part.

Limits

  • Depends on SAM finding an outline: if SAM misses the part, there is no box (checked sample: box shown on 68% of frames, 27 of 29 on the right object).
  • Large parts (wing, base) can exceed the 8% size limit or merge with the chassis outline.
